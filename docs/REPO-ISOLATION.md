# جداسازی کارها و استقلال از گیت‌هاب

این سند دو تضمین عملیاتی را ثبت می‌کند: (۱) استقرار تولید **هیچ وابستگی به گیت‌هاب ندارد**، (۲) کار موازی (اپ موبایل) نمی‌تواند کد بازبینی‌نشده را روی شاخهٔ `main` بگذارد.

## ۱. تولید به گیت‌هاب وابسته نیست

- استقرار فقط **کپی فایل** روی سرور است: `dist/server.cjs` → `C:\Servers\NIR\app\server.cjs` (+ آینهٔ `app\dist\server.cjs`)، دارایی‌های `dist\assets\*`، و `dist\index.html` (آخر از همه)، سپس ری‌استارت تسک `NIR Production Service`.
- هیچ GitHub Action، هوک، یا CI در مسیر اجرا/انتشار وجود ندارد؛ قطعی، محدودیت یا خصوصی‌شدن مخزن **هیچ تأثیری روی app.artadan.ir ندارد**.
- بکاپ/بازیابی هم محلی است: `DEPLOY-GUARD.ps1` (پیش از هر استقرار) + تسک شبانهٔ `NIR Daily Backup`.

## ۲. شاخهٔ `main` محافظت‌شده است (تضمین جداسازی)

تنظیمات فعال روی `main`:

| قاعده | وضعیت |
|---|---|
| تغییرات فقط از طریق Pull Request | ✅ (push مستقیم رد می‌شود: `GH006`) |
| اعمال اجباری برای ادمین‌ها (`enforce_admins`) | ✅ (دور زدن با توکن مالک هم ممکن نیست) |
| Force-push | ❌ ممنوع |
| حذف شاخه | ❌ ممنوع |
| الزام به تأیید (approval) | ۰ (چون حساب مالک تنهاست؛ PR لازم است ولی تأیید دوم نمی‌خواهد) |

**جریان کار رسمی برای هر تغییر (وب یا موبایل):**

```bash
git checkout -b <type>/<topic>      # مثلاً feature/mobile-otp یا fix/weighbridge-x
git add <files> && git commit -m "..."
git push origin <type>/<topic>
gh pr create --base main --head <type>/<topic> --title "..." --body "..."
gh pr merge --squash --delete-branch
git checkout main && git pull
```

> برای استقرار پس از merge: فایل‌های `dist` را (از نسخهٔ merge‌شده) با `DEPLOY-GUARD.ps1` بکاپ بگیرید و سپس کپی/ری‌استارت کنید.

## ۳. کار موازی موبایل

- **بک‌اند موبایل** (اندپوینت‌های `/api/mobile*`، جداول `otp_codes`, `device_tokens`, `delivery_proofs`, `farmer_orders` و ستون‌های `users.driver_id/farmer_id/phone`) داخل **همین مخزن** توسعه می‌یابد — اما **فقط از مسیر PR** وارد `main` می‌شود.
- **اپ‌های اندروید** (راننده/مرغدار/مدیر) در پوشهٔ `nir-mobile/` یا مخزن جدا نگه داشته می‌شوند؛ اگر داخل همین مخزن باشند، روی شاخهٔ خودشان و جدا از `main` کار می‌شوند تا بیلد و انتشار وب آلوده نشود.
- **مایگریشن ۰۰۰۴ افزودنی است و روی هر دو دیتابیس (`nir_db`, `nir_dev`) اعمال شده**؛ بنابراین بیلد وب و بیلد موبایل هر دو با هر ترتیبی کار می‌کنند و ورود کاربران نمی‌شکند.
- قاعدهٔ امنیتی: مایگریشن‌های جدید هم باید **افزودنی** باشند (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`) و پیش از هر تغییر روی تولید، `DEPLOY-GUARD.ps1` اجرا شود.
